# Retrieval evaluation

A synthetic corpus and a manual harness for the Memory v2 retrieval design. See [docs/memory-v2-build.md](../docs/memory-v2-build.md) section 4.

```bash
node eval/retrieval.mjs
```

Runs against PGlite, which is the same Postgres the test suite uses. Nothing to install and nothing to configure.

## Why this is not in `npm test`

`npm test` asserts that code does what it says. This measures whether retrieval is any good, which is a judgement a person makes by reading the output. An assertion here would either lock in today's scores, which move with the corpus, or assert something so loose it never fails.

What belongs in `tests/search.test.mjs` is the mechanisms this harness found, not its numbers: OR of lexemes rather than AND, summed IDF rather than `ts_rank_cd`, and `word_similarity` rather than `similarity`.

## The corpus

`corpus.json` is one invented person's accumulated context: 17 projects, 99 tasks, 413 memories, 75 prompts. Domains run from a Go payments ledger to sourdough, knee rehab, a Schengen visa and a wedding. Nothing in it is real.

It was generated by an agent that was given the schema and a quality bar, and no knowledge of the query design. That matters. A corpus written by the same person writing the query is a corpus that agrees with the query.

```
projects[]  slug, name, brief
tasks[]     slug, project|null, title, status, closed_at|null
memories[]  statement, source, band, project|null, task|null
prompts[]   text, context
```

Referential rules the file holds to: every `project` and `task` is an existing slug or null, a memory's scope matches its task's scope, `closed_at` is set exactly when `status` is `done`, and slugs are unique across the file.

## What it found

1. `websearch_to_tsquery` returns nothing for 71 of 75 prompts. It ANDs every term, and a prompt is a bag of words.
2. OR of lexemes hits 100%, which is the opposite failure. `ts_rank_cd` has no corpus statistics, so it returns 0.1 or 0.2 and nothing else, and `"go on"` ranks a memory about a Go service first.
3. Summed inverse document frequency ranks correctly. The right row comes first out of 413 on real prompts.
4. The floor is unsolved. Four candidate rules disagree on real prompts, and ratio based rules break on short ones. Settling it needs relevance labels over this corpus, which is the obvious next piece of work.
5. One miss no amount of tuning reaches: the user says "double-charge", the memory says "idempotency".

## Adding to it

Prompts are cheap to add and the most useful thing to add. Write what you would actually type, not what you think should match. A prompt that retrieves nothing is a result, not a bug.
