# Satchel design

Satchel looks like a personal notebook with physical controls. Paper is for what the user wrote. Hardware is for what the connected apps may do. The two never share a surface. Read this skill before touching `src/`, `design/` or any user-facing string.

## Source of truth, in order

1. [design/decisions.md](../../../design/decisions.md). Settled choices with dates and reasons. Do not re-argue them. If you must change one, add a new row at the top that says what it replaces and why.
2. [design/visual-direction.md](../../../design/visual-direction.md). Colour, type, controls, voice, motion, the mark.
3. [design/tokens.css](../../../design/tokens.css). The values. `src/styles/tokens.css` is a copy of it. Change both together.
4. [design/screen-map.md](../../../design/screen-map.md). Every route, which board it is, the component shape.
5. [design/copy.md](../../../design/copy.md). Every string, by page.
6. [design/acceptance.md](../../../design/acceptance.md). What "done" means per screen.
7. [design/accessibility.md](../../../design/accessibility.md). Tick every line before a screen is done.
8. The canvas boards in `design/canvas/boards/*.dc.html`, generated by `design/canvas/gen.mjs`. The hosted copy is linked from `design/README.md`.

Everything under `design/mockup/`, `design/prototype/` and `design/archive/` is history. Do not build from it.

## Rules that are easy to break

**Surfaces.** The hardware frame paints the outer box, the header and the rail. Paper is an inset panel. A memory is never drawn on hardware. A permission switch or an app control is never drawn on paper.

**Colour.** Use the tokens, never a hex value in a component. Orange (`--orange`) is only for selected controls and focus rings on hardware. On paper, links and accent text use `--accent`. Red is only for things that stop you or delete. Green appears only after something was actually verified. A light (LED) never stands alone. It always sits next to a word.

**Type.** Newsreader for what the user wrote and for page headings. Instrument Sans for interface text. DM Mono for readouts only: eyebrows, provenance, counts, the footer. Caveat is the wordmark and nothing else. Mono is never used for an action or for critical state.

**Controls.** Every clickable thing is a native `button`, `a href`, `input`, `select` or `textarea`. Nothing clickable on a `div`. Paper buttons are 40 px, radius 8. Rail items and hardware keys are 44 px. Use the pieces in `src/ui/` (Button, Chip, Light, Field, Notice, Sheet, Segments, Provenance, Empty) before writing new ones.

**The mark.** Never redraw it. The source is [design/mark/](../../../design/mark/): `mark.svg` at 32 px and up, `mark-small.svg` (no glyph) below that, `lockup.svg` for mark plus wordmark. In code use `SatchelMark` from `src/ui/SatchelMark.tsx`. Its rules live on the Mark board in `design/canvas/gen.mjs` and in `design/mark/README.md`: three parts only, the light is always orange, clear space equals the paper inset, never crop the frame. On a dark background (the header, the rail, any hardware) pass `ring` so a 1 px paper ring keeps the frame from sinking into the hardware.

**Motion.** One curve, `cubic-bezier(.2,.7,.2,1)`, three durations from the tokens. Errors, confirmations and the consent page never animate in. Reduced motion turns everything into a swap.

**Voice.** Address the user. Say the source and the destination: "Said on your phone", "Saved by Codex". Plain words, short sentences. No slogans inside working screens. An error says what failed, what is safe, and one thing to do. Take strings from `design/copy.md`. If a string is new, add it there first.

**States.** Every page needs empty, loading, error and success. Loading uses skeleton rows. Errors show in place with `role="alert"` and a Reload or retry. Success goes to the footer readout through `useFooter` and does not disappear on its own. Nothing is carried by colour alone.

**Routing.** Every destination and detail page has a real URL. Back and refresh must work. Scope lives in the `?scope=me|topic:<id>` query, see `src/app/scope.ts`.

## The Shelf

The Shelf is a shelf: things the person dropped, resting side by side. The rules from 5 Nov (`design/decisions.md`):

- **The object is the card.** A photo, the words (clamped to four lines, then More), a voice note as its round play key and length. Nothing else above the bottom line.
- **One quiet bottom line.** Kind, topic and time as provenance; the profile only when All is picked. Then two icon keys: ✎ (note) and ⋯ (move to Work or Personal, look for to-dos, remove). Icon keys are faint at rest, clear on hover or focus, always shown on touch, and each has an `aria-label`.
- **No form controls on a card at rest.** No select, no row of buttons. Anything done now and then goes in ⋯. A confirm (Remove) opens in place.
- **Voice is a key, never the browser's audio player.** `VoiceKey`: hardware-dark round key, orange while playing, a thin line that fills, the length in mono. One plays at a time.
- **One board.** List blocks and loose drops share one column-filled board, so nothing short sits under something tall. Lists are blocks (tick, title, detail under it; tap the title for source, move, remove), named by Satchel, never typed in.
- **The phone app follows the same rules** in Compose: same card, same keys, same board order.
- **Nothing pokes out of a card.** A card or block that is a grid uses `grid-template-columns: minmax(0, 1fr)`, so a line kept on one row (the bottom line) ellipses instead of widening the card. Check it by measuring, not by a scaled-down screenshot: in the browser, every child's right edge must sit inside its card at 1440, 1100 and 375 wide, with a voice note playing.

## Not in v1

Dark theme, phone layouts, Skills, Resume buttons, correction history view, account delete. Do not add them without a new decision row.

## How to work

- Find the board for the screen on the canvas and match it. If the board and the code disagree, the board wins unless a decision row says otherwise.
- Data comes from a repository in `src/features/<feature>/repository.ts` through `useStores`. Pages never build database queries.
- Run `npm run build` (this also type checks). Then open the page with the dev server and check every state, at 100% and 200% zoom, with keyboard only.
- If you changed shared CSS, run `node design/canvas/gen.mjs` so the boards pick it up, and check the boards still render.
- If you changed copy, update `design/copy.md` and, when the string is on a board, `design/canvas/gen.mjs`.
